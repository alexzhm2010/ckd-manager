# 🩺 个人肾病管理平台 (CKD Manager)

一个纯前端、零依赖部署的**慢性肾脏病（CKD）个人管理工具**，专为长期追踪肾功能、用药依从性与复查节奏设计。适合 CKD 3-5 期患者日常自我管理使用。

## ✨ 功能

| 模块 | 说明 |
|---|---|
| 🔐 登录 | 密码门禁：输入访问密码后才能查看详细数据，数据在本地解密；配置 Supabase 后可改用云端账号登录，多设备同步 |
| 🏠 首页 | 核心指标卡（eGFR/肌酐/尿蛋白/血钾，超标自动标红）、智能病情提醒、每日用药打卡、逾期复查待办 |
| ✍️ 记录 | 血压（≥140/90 自动预警）、饮水、体重+水肿、血钾症状自查（勾选≥2项弹就医警示）、症状备注 |
| 📈 指标 | 18 项指标互动趋势图（ECharts），带参考范围标线，支持手动录入新化验值 |
| 💊 用药 | 用药方案清单、近 7 天服药依从性图、用药安全红线（禁用药物提示） |
| 🏥 复查 | 复查倒计时、复查项目频率管理（自动判断逾期/临近）、就诊问题清单 |
| 📚 知识 | CKD 饮食红线（限盐/限钾/优质低蛋白/低嘌呤）、紧急就医信号、疾病知识 |

## 🔐 数据加密说明

仓库虽为公开，但**所有检验数据均为密文**，无密码无法读取：

- 加密算法：**AES-256-GCM**，密钥由访问密码经 **PBKDF2-SHA256（210,000 次迭代 + 随机盐）** 派生
- `history.js` 中只存储 `{salt, iv, ciphertext}`，**代码中不含明文密码，也不含密码哈希**
- 解密仅在浏览器本地进行，密码不发送到任何服务器
- 没有密码，任何人（包括仓库主人自己）都无法从代码反推出密码或还原数据

## 🚀 使用

纯静态页面，无需构建、无需后端：

- **在线（推荐）**：GitHub Pages 部署后，手机/电脑浏览器直接访问
- **本地**：需通过 http://localhost 或 https 打开（Web Crypto 解密要求安全上下文，直接双击 `file://` 打开会提示无法解密）

### 💾 数据存储

所有展示（趋势图、报告列表、首页指标）只读写同一张 `facts` 表：历史基线、每次导入的报告、手动补录，都是这张表里不同 `kind` 的行。

- **本地模式（默认）**：不需要任何后端，数据保存在浏览器 localStorage（`kidney_mgr_v1` 为内存模型缓存，`kidney_facts_v2` 为 facts 行缓存）。换设备时不自动同步。
- **云端模式（可选）**：按 [cloud-config.js](cloud-config.js) 顶部注释里的三步开通 Supabase，填入项目 URL 与 anon key 并重新发布。之后可用邮箱+密码登录，同一账号的数据在多台设备间同步，数据库侧由 RLS 保证每个账号只能读写自己的行。
- 首次启用云端时，可在首页「数据存储」卡片点「导入本机历史」，把 `history.js` 里的加密历史一次性解密并写入 facts（需输入原来的访问密码）。

## 📁 文件

```
├── index.html        # 应用主体（单文件，内含全部样式、逻辑与解密代码）
├── history.js        # 加密后的检验指标历史数据（ENCRYPTED_DATA，无密码不可读）
├── cloud-config.js   # Supabase 云端配置（留空即纯本地模式）
└── supabase/
    └── schema.sql    # 云端 facts 表结构、唯一索引与 RLS 策略
```

### 修改密码 / 更新数据

`history.js` 为密文，改动需重新加密：用新密码对明文数据执行 AES-256-GCM 加密（PBKDF2-SHA256 + 随机盐），生成新的 `ENCRYPTED_DATA` 覆盖原文件即可。

## 🔒 隐私说明

- 页面与数据已匿名化处理：无姓名、病历号、医院信息
- 历史基线数据加密存储于 `history.js`
- 启用云端模式后，已登录账号的数据会以明文行存入你自己的 Supabase 项目（由 RLS 限制仅本人可读写）；不启用则始终只在本机
- 如果你 fork 后要录入自己的数据，请用你自己的密码重新加密，并妥善保管密码（**密码遗失将无法恢复数据**）
