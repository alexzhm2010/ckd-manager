# 🩺 个人肾病管理平台 (CKD Manager)

一个纯前端、零依赖部署的**慢性肾脏病（CKD）个人管理工具**，专为长期追踪肾功能、用药依从性与复查节奏设计。适合 CKD 3-5 期患者日常自我管理使用。

## ✨ 功能

| 模块 | 说明 |
|---|---|
| 🔐 登录 | 仅邮箱注册/登录（Supabase Auth），数据在多台设备间同步；登录一次后自动保持会话 |
| 🏠 首页 | 核心指标卡（eGFR/肌酐/尿蛋白/血钾，超标自动标红）、智能病情提醒、每日用药打卡、逾期复查待办 |
| ✍️ 记录 | 血压（≥140/90 自动预警）、饮水、体重+水肿、血钾症状自查（勾选≥2项弹就医警示）、症状备注 |
| 📈 指标 | 18 项指标互动趋势图（ECharts），带参考范围标线，支持手动录入新化验值 |
| 💊 用药 | 用药方案清单、近 7 天服药依从性图、用药安全红线（禁用药物提示） |
| 🏥 复查 | 复查倒计时、复查项目频率管理（自动判断逾期/临近）、就诊问题清单 |
| 📚 知识 | CKD 饮食红线（限盐/限钾/优质低蛋白/低嘌呤）、紧急就医信号、疾病知识 |

## 🔐 账号与数据

- 只有一个账号入口：**邮箱 + 密码**（Supabase Auth 负责注册、登录与会话保持），没有本机访问密码。
- 所有检验数据（历史基线、每次导入的报告、手动补录）都存在你自己的 Supabase 项目里，由 RLS 保证每个账号只能读写自己的行。
- 本机只保留一份 localStorage 缓存，用于断网/首屏快速渲染；不与云端冲突，按更新时间合并。
- 首次在已有数据的设备上登录时，本机缓存里较新的数据会自动补传到云端。

## 🚀 使用

纯静态页面，无需构建、无需后端：

- **在线（推荐）**：GitHub Pages 部署后，手机/电脑浏览器直接访问
- **本地**：直接打开 `index.html` 即可（图表库需联网从 CDN 加载）

### 💾 数据存储

所有展示（趋势图、报告列表、首页指标）只读写同一张 `facts` 表：历史基线、每次导入的报告、手动补录，都是这张表里不同 `kind` 的行。

- 按 [cloud-config.js](cloud-config.js) 顶部注释里的三步开通 Supabase，填入项目 URL 与 anon key 并重新发布。
- 用邮箱注册/登录后，同一账号的数据在多台设备间同步，数据库侧由 RLS 保证每个账号只能读写自己的行。
- 本机 localStorage（`kidney_mgr_v1` 为内存模型缓存，`kidney_facts_v2` 为 facts 行缓存）只作缓存，云端才是数据源。

## 📁 文件

```
├── index.html        # 应用主体（单文件，内含全部样式与逻辑）
├── cloud-config.js   # Supabase 云端配置
└── supabase/
    └── schema.sql    # 云端 facts 表结构、唯一索引与 RLS 策略
```

### 更新数据

直接在页面里补录、导入化验报告即可；数据会写入 `facts` 表并同步到云端，不需要改代码或重新加密。
